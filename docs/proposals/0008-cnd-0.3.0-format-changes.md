# Proposal — CND 0.3.0 format changes

## Status
Draft. Implementation vehicle for the 0.3.0 breaking wave. It carries the
concrete schema/spec/model diff for the field changes below and for the
schema-shape consequences of ADRs 0015 (identity), 0016 (hashing) and 0017
(label-keyed links), so the whole wave lands as one `cnd_version` bump.

## Motivation
Confronting the models with what a producer that is *not* a paginating
compiler can supply — a hand author, a language model, a markdown/HTML/DocLang
converter — surfaced a class of defects the format had carried unnoticed:
several **required** fields cannot be supplied without a compiler, and several
others are **derivable** and should never have been serialised.

The criterion applied throughout, already endorsed by the spec for positions
(§2) and by ADR 0012: *a field is legitimately required only if no conformant
producer can omit it without losing information the consumer cannot
reconstruct.*

## Proposed change

### Links carry the target label only (ADR 0017)
The `id` field is removed from `refs`/`cites`/`footnotes`; an edge is
`{label, text_span?}` (`cites` keeps `form`/`supplement`). Resolution is by a
`label → target` index; the domain is the field the edge sits in. Labels
become globally unique within a CND, mirroring the id-uniqueness rule
(§2); the `link.label == target.label` mirror is removed as vacuous; a node
`label` is required for any node that is a `refs` target. Rationale and
consequences are in ADR 0017.

```json
// before                         // after
{"id":"…","label":"lst-api",      {"label":"lst-api",
 "text_span":[29,38]}              "text_span":[29,38]}
```

### `raw_typst` → `raw: {format, value}` (B2)
On `table`, `math`, `figure`, the producer's verbatim source becomes a typed
object, not a bare string:

```json
"raw": {"format": "typst", "value": "$ e(t) = m(t) - r(t) $"}
```

`format` is an **open string** (`"typst"`, `"latex"`, `"mathml"`…), same
precedent as `source.type` below and `figure.kind`. A bare string dropped the
one thing a consumer needs to decide whether to attempt a parse: which
language the content is in. The field stays optional and stays the escape
hatch for an unconvertible figure body (`children: []` with `raw` filled).

### `number`: one field, resolved value, nullable (B3)
`heading.numbering`, `math.numbering` and `figure.fig_number` collapse into a
single nullable `number`. It carries the **resolved value as displayed** —
`"2.1.1"`, `"(1)"`, `"3"` — never a pattern. The counter-label word is
excluded: `"Figure 3"` bakes a locale into data (Figure / Abbildung / Figura)
and composing the prefix is a rendering decision. A consumer cannot recompute
a number without reimplementing the counter engine, so the resolved value is
the only useful capture; the pattern is a styling detail with no downstream
value. Producers already emit resolved values — this makes the field honest,
and requires the Typst producer to stop emitting the counter word in
`fig_number`.

### `location` nullable; pagination is all-or-nothing (B4)
`location` becomes nullable. Normative invariant: **either every node carries
a `location`, or none does** — a partially paginated CND is a validation
error, which removes the "unknown page" vs. "not paginated" ambiguity without
a new field. `location`'s original justification (§2 — page breaks are not
reconstructible from the tree) holds only for a paginated document; markdown,
HTML and hand-authored sources have no pages, and forcing `page: 1` there
fabricates data indistinguishable from a real page 1.

`paginated` is **not a field**: it is a computed property the SDK exposes,
derived from whether the nodes carry a `location`. Serialising a derivable
boolean would contradict the principle this whole proposal applies (ADR
0008/0012). To specify: the page-derived traversal positions
(`page_index`/`page_count`) are undefined/absent when the document is not
paginated.

### `BibEntry`: `rendered` → `formatted`, nullable, with a content floor (B5)
`rendered` is renamed `formatted` — "rendered" collided with §7's renderer
vocabulary, where rendering is explicitly *not* part of the format. It becomes
nullable: requiring it presupposes a CSL style engine ran, which a hand author
or a markdown converter has not. Validation floor: an entry must carry
`formatted`, or structured fields, or both — never an empty, unconsumable
entry (see open question on the structured-field model).

### Provenance and defaults (B7)
- `compiled_at` → **`built_at`**, still required in the CND: generalises
  past "compilation".
- New nullable **`source: {type, hash, uri?}`** block. `doc` stays separate:
  it identifies the *work* (title, authors), `source` the *input artifact*.
  The same work can be compiled from Typst then re-imported from DocLang.
  - `type` — open string (`"typst"`, `"markdown"`, `"doclang"`…).
  - `hash` — self-describing (`"sha256:…"`), replacing the top-level
    `doc_hash`. Comparability contract (normative prose): comparable only
    between two CNDs from the **same producer over the same source**;
    equal ⇒ unchanged, different ⇒ changed; cross-producer comparison is
    meaningless. This retires ADR 0002's second clause (`doc_hash` as the sole
    hash-field name).
  - `uri` — optional, **never promised resolvable**; an identifier in the
    producer's own space, not a path a consumer may dereference (an absolute
    workstation path would leak the filesystem tree).
- `doc.authors` and `doc.keywords` gain a default of `[]` and become
  omittable, matching each other.

### Spec wording that ships in the same wave
- §4: "Stable node identifier" → ids are **unique per CND, non-durable**;
  durable identity is via labels or the diff facility (ADR 0015).
- §2/§5: global label uniqueness and label-keyed resolution (ADR 0017).
- Derived content hash `node_hash`/`content_hash`, RFC 8785 (JCS) + NFC,
  never serialised (ADR 0016) — SDK functions plus a normative algorithm note.

## Alternatives considered
- **`paginated` as a serialised boolean.** Rejected — derivable from node
  `location` presence; serialising it repeats the redundancy ADR 0012 deleted.
- **`number` as the pattern (`"1."`, `"(1)"`).** Rejected — a consumer cannot
  replay the counter engine, so only the resolved value is usable; the pattern
  is a rendering concern.
- **Rename `doc` to `source`.** Rejected — the work and the input artifact are
  different identities that diverge (one work, many source formats).
- **`source.type` / `raw.format` as closed enums.** Rejected — markdown, HTML
  and DocLang producers are already planned; a closed enum needs a spec
  revision per producer. Open strings with an informative known-values list,
  same as `figure.kind`.

### Vocabulary and file identity (ADR 0021)

The wave also carries the rename decided in ADR 0021: "manifest" is retired,
the built artifact becomes **the CND** (`.cnd`), and the source form becomes
**the declaration** (`.decl.yaml`). Concretely in this repository:
`CndManifest` → `Cnd`, `src/cnd/core/manifest.py` → `cnd.py`,
`spec/schema/cnd-manifest.schema.json` → `schema/cnd.schema.json`,
`tests/test_manifest.py` → `test_cnd.py`, and the five `*_manifest.json`
fixtures → `*.cnd`.

This is a **sweep, not a find-replace** — 441 prose and code occurrences — and
it must land in the same pass as the code rename so prose and code never
disagree. ADR 0006's title keeps the retired word permanently, which is
harmless because the word there still means what it always meant.

## Impact
Breaking, `cnd_version` 0.3.0. Every consumer and producer is affected:
- Producers stop emitting edge ids and the `number` counter word, must supply
  unique labels, and move to the `source` block / `built_at`. The reference
  Typst producer changes accordingly (tracked in its own repo).
- Fixtures are rewritten to the new shapes.
- `paginated`-derived positions on unpaginated documents need SDK handling.
