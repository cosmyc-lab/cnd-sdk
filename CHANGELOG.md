# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html)
(semver-zero discipline: while on `0.y.z`, breaking changes and additions bump
the minor version, fixes bump the patch version).

## [0.4.0] - 2026-07-23

SDK release 0.4.0 implements CND **format 0.3.0** (`cnd_version: "0.3.0"`).
The wave is docs/proposals/0008, carrying ADRs 0015-0017 and 0021.

### Changed (breaking)

- **"Manifest" is retired from the vocabulary** (docs/adr/0021): the built
  artifact is *the CND* (`.cnd`), the source form is *the declaration*.
  `CndManifest` -> `Cnd`, `src/cnd/core/manifest.py` -> `cnd.py`,
  `spec/schema/cnd-manifest.schema.json` -> `schema/cnd.schema.json`.
- **Links carry the target label only** (docs/adr/0017, superseding 0002):
  `id` is removed from `refs`/`cites`/`footnotes`; an edge is
  `{label, text_span?}`. Labels are globally unique within a CND, and the
  `link.label == target.label` mirror is gone as vacuous. `incoming()`
  re-keys from UUID to label, and the new `Cnd.resolve(label)` is the
  label index. An edge keys on the label because an id is not durable
  (docs/adr/0015) — an edge carrying one would expire at the next build.
- **`raw_typst` -> `raw: {format, value}`** on `table`, `math`, `figure`.
  A bare string dropped the language a consumer needs in order to decide
  whether to attempt a parse.
- **`heading.numbering`, `math.numbering` and `figure.fig_number` collapse
  into one nullable `number`**, carrying the resolved value as displayed
  (`"2.1.1"`, `"(1)"`, `"3"`) — never the pattern, and never the
  counter-label word, which bakes a locale into data.
- **`location` is nullable and pagination is all-or-nothing.** A markdown
  or hand-authored source has no pages, and `page: 1` there fabricates
  data. `Cnd.paginated` is derived, not a field. `page_index`/`page_count`
  on a traversal context are now `int | None` — undefined, not zero.
- **`BibEntry.rendered` -> `formatted`, nullable** (requiring it
  presupposes a style engine ran), and **`BibEntry.raw` -> `fields`**,
  since `raw` now means `{format, value}` on nodes.
- **`compiled_at` -> `built_at`**; the top-level `doc_hash` becomes
  **`source: {type, hash, uri?}`**, kept separate from `doc` because the
  work and the input artifact are different identities.
- `doc.authors` gains a `[]` default, matching `keywords`.

### Added

- **`validate(cnd)`** — the invariants JSON Schema cannot express: global
  label uniqueness, per-family link domains, pagination all-or-nothing,
  and the `BibEntry` content floor. Returns every violation rather than
  the first.
- **`node_hash()` / `content_hash()`** (docs/adr/0016) — derived, never
  serialized. RFC 8785 (JCS) over the hashable subset, strings normalised
  to NFC first. Adds `rfc8785` as a dependency: ECMAScript number
  formatting is where an independent implementation silently diverges.
- **Spec sections 8-10** now state traversal semantics, validation and
  hashing normatively, answering the two questions docs/adr/0019 left
  open: the out-of-tree pools do **not** enter reading order, and the
  three link families are enumerated in a fixed order that carries no
  positional claim (`text_span` is the only positional truth).
- **The `cnd` conformance CLI** (ADR 0020) — `validate`, `hash` and
  `inspect`, with `--json` output and exit codes as part of the contract
  (`0` conformant, `1` not). It is the executable oracle of the fixture
  corpus: the tool an SDK author in another language uses to answer "does
  my implementation agree?". This is **three of the five** conformance
  verbs ADR 0020 specifies: `build` (from a declaration) and
  `reconcile`/`diff` await the features they act on, and the corpus
  likewise carries two of the four required vector kinds. `cnd declare`
  is a different kind of absence — it belongs with the producers
  permanently, since bundling it would make the hub depend on a
  satellite.
- **Conformance vectors** in the corpus: `fixtures/hashes.json`
  (CND -> expected hash) and `fixtures/traversal.json`
  (CND -> expected id sequence), regenerated by `scripts/`.
- **`fixtures/unpaginated.cnd`** — the case this wave makes possible: no
  locations, a bibliography entry with structured fields and no
  `formatted`, omitted metadata defaults.
- **`counter_label`** on `heading`/`math`/`figure` (proposal 0010) — the
  word displayed in front of `number` ("Figure", "Tabelle"), as resolved
  in the document's language. Splitting it out of `number` was right;
  dropping it was not. A producer resolves it from the element kind and
  the language using a table no consumer has, and for an author-defined
  `kind` there is no table at all — the author supplies the word and
  nothing else in the CND encodes it. Excluded from the content hash for
  the same reason `number` is.

## [0.3.0] - 2026-07-18

SDK release 0.3.0 implements CND **format 0.2.0** (`cnd_version: "0.2.0"`).

### Changed (breaking)

- **Forward-only cross-references** (docs/adr/0008): `refs_from` is removed
  from every node; `refs_to` is renamed to `refs`. The reverse index is now
  derived, never serialized — use the new `CndManifest.incoming(node_id)`,
  built lazily and cached on the instance.
- **`to_text()` removed from every node**, along with
  `cnd.core.node_text.render_node_text()`. Nodes are pure data; rendering
  moved to a renderer hierarchy in `cnd.core.render`: the `NodeRenderer`
  ABC (one method per node type plus a concrete `render()` dispatch) and
  `MarkdownRenderer`, whose table/figure verbosity is constructor
  configuration (`tables=` / `figures=`: `"placeholder"` | `"inline"` |
  `"auto"`). "Raw" is not a renderer — it is Pydantic's own
  `repr()`/`model_dump_json()`.
- **`FigureNode` is now a wrapper node**: it gains `children` and loses
  `path` and `alt` (moved to the new `ImageNode`). `kind` remains an open
  string counter/label selector, never a content discriminator. Nested
  figures (subfigures) are allowed.
- **`TableNode` loses `caption` and `fig_number`** — they live on the
  wrapping `FigureNode`. A bare table is a `TableNode` with no wrapper; no
  deprecated fields are left behind.
- **Traversal descends into every children-bearing node** (`heading` and
  now `figure`); prune with a `stop_predicate` to treat figures as atomic.
- **`NodeLocation` reduced to layout facts only** (docs/adr/0012): a single
  `page` field (the page the node begins on). `span`, `page_span`,
  `parent_span`, `span_count`, and `NodeLocation`'s span-based ordering are
  removed. Reading order is now a normative invariant of the tree, and the
  traversal engine derives positions onto every `NodeTraverseContext`:
  `doc_index`/`doc_count`, `sibling_index`/`sibling_count`,
  `page_index`/`page_count` (1-based; totals from a cached pre-pass;
  pruning does not shift positions).
- `cnd.core.node_text` is now internal plumbing for renderers:
  `figure_node_placeholder` removed, `table_node_placeholder` and
  `render_table_markdown` no longer emit caption/number (the wrapper owns
  them), `_header_row_text` renamed to `header_row_text`.
- `NodeDisplayVisitor` consumes a `NodeRenderer` for text previews
  (`renderer=` parameter), displays `refs`/`cites`/`footnotes` (with spans)
  instead of `refs_to`/`refs_from`, and handles the new node types.

### Added

- **Link families on every node**: `refs: list[NodeRef]`,
  `cites: list[CiteRef]` (resolving in the bibliography pool, with `form`
  and `supplement`), `footnotes: list[FootnoteRef]` (resolving in the
  footnotes pool). All share the `{id, label, span?}` skeleton; `span` is
  an optional `[start, end)` pair of Unicode code-point offsets into the
  containing node's rendered text (additive to the canonical `NodeRef`
  shape — docs/adr/0002 intact).
- **Top-level pools on the manifest**: `bibliography: list[BibEntry]`
  (rendered string + curated typed subset + lossless `raw` JSON
  passthrough) and `footnotes: list[Footnote]` (flat text). Ids are
  globally unique across nodes and pool entries.
- **New node types**: `TermsNode` (`type: "terms"`, definition list of
  `TermItem` pairs) and `ImageNode` (`type: "image"`, leaf image with
  `path`/`alt`).
- New fixture `fixtures/rich_content_manifest.json` exercising terms,
  figure-wrapping-code, images, citations + bibliography, and footnotes.

### Format

- `cnd_version` bumped `0.1.0` → `0.2.0`; spec §5 rewritten (forward-only
  edges, link families, standoff spans, global id uniqueness), new
  out-of-tree entities section, node-type updates (figure wrapper, image,
  terms, table without caption), rendering documented as SDK non-normative.
